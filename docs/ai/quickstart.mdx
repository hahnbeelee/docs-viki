This quickstart walks you through sending your first request to the Yelp AI API, understanding the response structure, and continuing the conversation with a follow-up question. By the end you'll have working code in both Python and curl that you can adapt immediately for your own application.

## Prerequisites

Before you begin, make sure you have:

- A **Yelp Places API key** on the **Premium plan** (AI API access requires Premium). If you don't have one, sign up at the [Yelp Places API page](https://business.yelp.com/data/products/places-api/) and review the [authentication guide](/docs/fusion-authentication).
- Basic familiarity with HTTP requests and JSON.
- A terminal (for curl) or a Python 3 environment with the `requests` library installed (`pip install requests`).

<Steps>

### Get your API key

Log in to the [Yelp Developer Portal](https://business.yelp.com/data/products/fusion) and copy your API key from the dashboard. Store it securely — never hard-code it in production code. For the examples below, substitute `your_api_key_here` with your actual key.

### Send your first request

Your first request doesn't need a `chat_id`. The API creates a new conversation session for you and returns a `chat_id` in the response that you use for follow-ups.

<CodeGroup>

```python Python
import requests

YELP_API_KEY = "your_api_key_here"
url = "https://api.yelp.com/ai/chat/v2"

headers = {
    "Authorization": f"Bearer {YELP_API_KEY}",
    "Content-Type": "application/json"
}

data = {
    "query": "Find the best pizza places in San Francisco"
}

response = requests.post(url, headers=headers, json=data)
print(response.json())
```

```bash curl
curl -X POST "https://api.yelp.com/ai/chat/v2" \
  -H "Authorization: Bearer your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "Find the best pizza places in San Francisco"
  }'
```

</CodeGroup>

<Tip>
  Add a `user_context` object with `latitude` and `longitude` to get location-aware results. See the [overview](/docs/ai/overview) for the full field reference.
</Tip>

### Understand the response

A successful response looks like this (abbreviated):

```json

Golden Boy Pizza is famous for Sicilian-style squares with a thick, focaccia-like crust. That's Amore Woodfire Pizza features authentic wood-fired pies made with a Stefano Ferrera oven from Naples.",

      {
        "tag_type": "business",
        "start": 66,
        "end": 89,
        "meta": { "business_id": "mSMZJj2pFvttWLpcDmgrEA" }
      },
      {
        "tag_type": "highlight",
        "start": 98,
        "end": 136
      }
    ]
  },
  "types": ["business_search"],
  "entities": [
    {
      "businesses": [
        {
          "id": "mSMZJj2pFvttWLpcDmgrEA",
          "name": "Tony's Pizza Napoletana",
          "rating": 4.2,

          },

          }
        }
      ]
    }
  ],
  "chat_id": "N1u996U6HInvhrCaedrb1Q"
}
```

Here's what the key fields mean:

| Field | Description |
|---|---|
| `response.text` | The AI's natural-language answer — ready to display to users |
| `response.tags[]` | Spans in `response.text` marking business names (`tag_type: "business"`) and highlighted phrases (`tag_type: "highlight"`), with `start`/`end` character positions |
| `response.tags[].meta.business_id` | Links a business name in the text to its full entity in `entities[].businesses[]` |
| `types` | Describes the response type: `"business_search"`, `"business_question"`, or `"reservation"` |
| `entities[].businesses[]` | Structured business data including name, address, rating, price, categories, photos, hours, and AI-generated summaries |
| `chat_id` | Your session ID — **save this value** and pass it in the next request |

### Continue the conversation

To ask a follow-up question about the same businesses, include the `chat_id` from the previous response:

<CodeGroup>

```python Python
chat_id = "N1u996U6HInvhrCaedrb1Q"  # from the previous response

data = {
    "query": "What are their opening hours?",
    "chat_id": chat_id
}

response = requests.post(url, headers=headers, json=data)
print(response.json())
```

```bash curl
curl -X POST "https://api.yelp.com/ai/chat/v2" \
  -H "Authorization: Bearer your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "What are their opening hours?",
    "chat_id": "N1u996U6HInvhrCaedrb1Q"
  }'
```

</CodeGroup>

## Session Expiry

<Note>
  Chat sessions expire after a period of inactivity. If you send a request with a stale `chat_id`, the API will treat it as a new conversation. Design your application to handle session resets gracefully — for example, by detecting when the response returns different businesses than expected and prompting the user to start a new search.
</Note>

## Error Handling

If your request is malformed or you've exceeded your daily call limit (20 calls/day on the Premium plan), the API returns a standard HTTP error code. A `429` response means you've hit the rate limit; a `401` means your API key is invalid or missing. For the full list of error codes, see the [AI API Reference](/reference/ai-chat).
